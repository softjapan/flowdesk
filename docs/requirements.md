# FlowDesk 要件定義書

## 1. 概要

FlowDesk は、美容室・整体院・相談窓口など「スタッフが顧客の予約を受けて対応する」小規模事業者向けの、予約・顧客・スタッフ管理 SaaS である。
1 つのシステムを複数の事業者（テナント）が利用し、事業者ごとにデータを完全に分離する。

## 2. 用語

| 用語 | 意味 | DB 上の実体 |
|------|------|-------------|
| 組織（テナント） | FlowDesk を契約する事業者 | `organization` |
| 店舗 | 組織が持つ拠点 | `location` |
| メンバー | 組織に所属するログインユーザー。ロールは Owner / Admin / Staff | `member`（Better Auth organization プラグイン） |
| スタッフ | 予約を担当するメンバー（Staff ロールに限らない） | `member` + `staffProfile` |
| 顧客 | 組織の顧客。ログインしない | `customer` |
| メニュー | 予約できるサービス（所要時間・料金） | `service` |
| 予約 | 顧客・スタッフ・メニュー・日時の組み合わせ | `reservation` |

## 3. 利用者とロール

| ロール | 想定する人 | できること（詳細は authz-matrix.md） |
|--------|-----------|------------------------------------|
| Owner | 経営者。組織に 1 人以上 | すべて。契約プランの変更、組織の削除 |
| Admin | 店長 | 店舗・メニュー・スタッフ・顧客・予約の管理。課金と組織削除は不可 |
| Staff | 現場スタッフ | 顧客の閲覧と登録、予約の作成・変更。自分の予約が中心 |

## 4. 機能要件

| ID | 機能 | 章 | 優先度 |
|----|------|----|--------|
| F-01 | メールアドレスとパスワードでの登録・ログイン・ログアウト | 8 | 必須 |
| F-02 | パスワード再設定（メールのリンク） | 8・11 | 必須 |
| F-03 | 組織の作成と、メンバーの招待（メール） | 10 | 必須 |
| F-04 | ロールの変更・メンバーの削除 | 10 | 必須 |
| F-05 | 店舗の CRUD | 9 | 必須 |
| F-06 | メニューの CRUD | 9 | 必須 |
| F-07 | 顧客の CRUD と検索（氏名・電話・メール） | 9 | 必須 |
| F-08 | 予約の作成・変更・キャンセル | 9 | 必須 |
| F-09 | 同じスタッフの予約時間の重複を防ぐ | 9・15 | 必須 |
| F-10 | ダッシュボード（今月の予約数・顧客数・売上・予約推移・本日の予約） | 6・15 | 必須 |
| F-11 | 顧客一覧の CSV エクスポート（非同期、完了をメール通知） | 11 | 必須 |
| F-12 | 顧客写真・添付ファイルのアップロード（S3） | 11 | 必須 |
| F-13 | 予約確定・前日リマインドのメール送信（SQS + Worker） | 11 | 必須 |
| F-14 | 料金プラン（Free / Pro）とサブスクリプション（Stripe） | 12 | 必須 |
| F-15 | プランによる機能制限（Free はスタッフ 2 人・店舗 1 つまで） | 12 | 必須 |
| F-16 | 監査ログ（誰が・いつ・何を変更したか）の記録と閲覧 | 10・14 | 必須 |

## 5. 非機能要件

| ID | 要件 | 検証方法（章） |
|----|------|---------------|
| N-01 | 他組織のデータは、URL や ID を書き換えても読めない・書けない | 権限漏れを検出する E2E テスト（14） |
| N-02 | 認可はサーバー側の Service 層で必ず検証する。画面で非表示にするだけにしない | 単体テスト・コードレビュー（10・13） |
| N-03 | 予約の重複は同時リクエストでも発生しない（DB 制約で保証） | 並行実行テスト（9・15） |
| N-04 | 一覧画面は顧客 1 万件・予約 10 万件で p95 500ms 以内 | 計測と N+1 の解消（15） |
| N-05 | シークレットはリポジトリに置かない。本番は AWS Secrets Manager | Hooks・CI のチェック（2・17） |
| N-06 | DB は毎日バックアップし、手順書どおりに復旧できる | 復旧演習（18） |
| N-07 | ローカル環境は `docker compose up` だけで起動できる | 第4章の完成タグ |
| N-08 | AWS を使わなくても、本書のローカル部分（第1〜15章）を完走できる | S3・SQS・メールはローカル代替（MinIO・ElasticMQ・Mailpit） |

## 6. 範囲外

- 顧客自身によるオンライン予約（公開予約ページ）
- 多言語対応・複数通貨
- ネイティブアプリ
